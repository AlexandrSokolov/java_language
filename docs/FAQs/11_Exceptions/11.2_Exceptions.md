
### What to keep in mind handling NPE?
<details><summary>Show answer</summary>

The problem is unique to NPE: a well-written exception says what went wrong in its message ("email is required"),
but a null dereference historically said almost nothing. So NPE is the one exception where the message alone rarely
lets you act, and the design has to work harder to make it locatable.

**Before (pre-JDK 15).** A null dereference threw with a **null message** — the code did `throw new
NullPointerException()` implicitly, no string. `toString()` gave you the class name alone: `java.lang.NullPointerException`,
nothing about *what* was null or *where*. In an expression like `a.b.c.d`, you could not tell which link was null
without a debugger or a full stacktrace dump.

**Now, default compile (JDK 15+, no flags).** JEP 358 rewrote the message to name the null reference:
`Cannot invoke "String.getHost()" because "<local2>" is null`. You learn the failed operation and *that* a local was
null — but by a synthetic name (`<local2>`), because the local's real name is not in the class file without debug info.

**With debug info (`javac -g`).** The synthetic name becomes the source name: `... because "config" is null`. Now the
message reads like your code. Still **no line number** — helpful-NPE names the reference, never the line.

**What you extend to get full context.** Two additions, each closing a different gap:

- **Caller context** — the failing spot knows what was null, not *why it was called* (which object, which run). Only
  the caller has that. Pass it in and attach it to the failure: `tenant 9002 nightly run -> ...`.
- **Throw site, not the whole stack** — `error.getStackTrace()[0]` is one `Class.method(File:line)` line: the exact
  spot, no stack dump. For a wrapped chain, walk `getCause()` and take `[0]` of each link — guard the walk with an
  identity check (`IdentityHashMap`), because a self-referential cause loops forever.

Rule of thumb: 
- message names *what* was null (free, JDK 15+), 
- `-g` makes the name real, 
- caller context adds *why*,
- `getStackTrace()[0]` adds *where* — pick the level the reader needs.
