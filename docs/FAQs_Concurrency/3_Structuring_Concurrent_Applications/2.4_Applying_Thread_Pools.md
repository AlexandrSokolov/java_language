### Cached vs fixed thread pool — which to use?
<details><summary>Show answer</summary>

Depends on load:

- **`newCachedThreadPool`** — no configuration, does the right thing for a small program or a lightly loaded server.
  But it doesn't queue tasks: if no thread is free, it makes a new one. On a heavily loaded server that's dangerous —
  more tasks arriving on a maxed-out machine spawn more threads, making things worse.
- **`newFixedThreadPool`** — a fixed number of threads, so load can't spawn unbounded threads. The right default for
  a heavily loaded production server. For full control, use `ThreadPoolExecutor` directly.

Rule of thumb: cached for small or lightly loaded, fixed (or `ThreadPoolExecutor`) for production under real load.
