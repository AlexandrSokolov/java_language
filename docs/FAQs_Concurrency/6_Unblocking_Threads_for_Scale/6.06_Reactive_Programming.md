Event loop (Why is it here?)
An "event loop" is the engine behind Reactive frameworks (like Spring WebFlux or Node.js), 
where a single thread handles thousands of connections. 
Calling .join() on an event loop thread freezes the entire server. 
However, if you are studying standard Spring MVC and Java Concurrency (not WebFlux), 
this is totally irrelevant to you right now. It is distracting trivia. We should delete it.

This is related to: `What does waiting on a future cost?` card

Event loop. Some servers (Netty, Spring WebFlux) don’t use one thread per request. 
A few threads, usually one per CPU core, each serve thousands of connections by running short callbacks one after another. 
That thread is the event loop. If you block it, every connection it serves stops. 
Worse, if the reply you wait for must itself be handled by that same thread, it can never arrive, so you wait forever. 
It’s a real trap, but it needs the event loop explained first, and your deck hasn’t done that.
