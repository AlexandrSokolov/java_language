### What breaks when threads share an object?
<details><summary>Show answer</summary>

- An object can be shared between all threads in a process.
- Any thread holding a reference can change it.
- The OS can swap threads on and off cores at any time.
- So a swap can leave a method half-done and the object in a broken state.
- Objects can be locked to protect the vulnerable data.
- Without locking, changes made in one thread may not be seen correctly in others.

Lock it: in Java the tool is `synchronized`.

</details>

### What requirement do threaded methods carry?
<details><summary>Show answer</summary>

A running method must be interruptible — the OS has to be able to swap it off the core at any point. Otherwise a
method with an infinite loop would hold the CPU forever and starve every other thread.

The cost of that requirement: a swap can land in the middle of a method, leaving the object it was updating
half-finished — which is exactly why shared objects then need locking.

</details>
