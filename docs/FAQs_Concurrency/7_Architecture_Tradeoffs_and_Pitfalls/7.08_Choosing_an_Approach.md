# 7.07 Choosing an Approach

Picking a concurrency model for a given problem, and saying why. Plain threads and executors vs CompletableFuture vs
virtual threads vs reactive code; a direct call vs a message on a queue; more threads in one instance vs more
instances; a lock vs a version check vs a single writer. The deciding factors: waiting on I/O vs busy on CPU,
latency vs throughput, ordering, failure handling, and how hard the code is to debug and run.

Draws on 7.01–7.06. Cards here are mostly design challenges, not single facts.
