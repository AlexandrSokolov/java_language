### How do you stop one thread from another?
<details><summary>Show answer</summary>

Have the thread poll a `boolean` flag: it starts `false`, and another thread sets it `true` to ask the
running thread to stop itself. The running thread checks the flag between iterations and returns when it
sees `true`.

This is for a thread doing a long, heavy job — one that runs its own loop long enough to need checking a
flag partway through. Never use `Thread.stop`: it was deprecated long ago because it can leave data
half-written and corrupted.

For work that splits into small, short tasks, there is an alternative design where no thread needs
stopping at all — you stop handing out new work and let the running pieces finish. Covered separately.

</details>

### How do you shut an executor down, and why must you?
<details><summary>Show answer</summary>

Call `shutdown()` on the executor service. It stops accepting new tasks and lets already-submitted ones finish —
a graceful wind-down.

You **must** do it: an executor's threads keep the VM alive. Forget `shutdown()` and the program likely won't exit —
it hangs with nothing left to do, held open by idle pool threads.

```java
exec.shutdown();
```

</details>

### How does Future.cancel work?
<details><summary>Show answer</summary>

`cancel(boolean mayInterruptIfRunning)` does **not** guarantee the task stops. What it does depends on the task's
state:

- **Not started yet** → removed from the queue, never runs. Clean cancel.
- **Already running** → the boolean decides: `cancel(true)` interrupts the running thread; `cancel(false)` leaves
  it running and only marks the `Future` cancelled.
- **Already finished** → does nothing, returns `false`.

The trap: `cancel(true)` only **interrupts** — a request, not a kill. It stops the task only if the task
**cooperates**: it calls a blocking method that responds to interrupt (`sleep`, `wait`, interruptible I/O), or it
checks the flag itself in its loop. A tight CPU loop that never checks runs to the end and ignores the cancel.
Java has no force-kill for a thread by design.

```java
Future<?> f = pool.submit(() -> {
  while (!Thread.currentThread().isInterrupted()) {   // checks → can be cancelled
    doChunk();
  }
});
```

Handle: cancellation is cooperative — `cancel(true)` asks the task to stop, and only a task written to notice the
interrupt actually will.

</details>
