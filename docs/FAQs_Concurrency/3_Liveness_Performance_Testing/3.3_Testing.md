### Measuring how fast a small piece of code runs?
<details><summary>Show answer</summary>

Don't hand-roll it — use a benchmarking harness such as JMH.

A simple `nanoTime` before/after gives misleading numbers on small code because the JVM reshapes it as it runs:
the JIT hasn't warmed up on the first runs so early timings are slow, dead-code elimination can delete work whose
result you never use, and GC or inlining can land inside your measured window. The result looks precise but isn't
real.

A harness handles this for you — warmup runs, many iterations, and consuming results so the JIT can't optimize
the work away. Reach for one whenever the thing you're timing is short.
